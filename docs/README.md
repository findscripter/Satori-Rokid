## 项目做了什么

Satori（CHI 2025）研究主动式 AR 助手：系统先理解环境和用户正在做什么，再推断用户的目标和下一步，在合适的时机给出指导。论文用 Belief–Desire–Intention（BDI）组织这种用户建模。

本仓库按这一思路做了独立的研究原型：

- **方法后端**：多帧观察 → 环境与行为理解 → 目标提议 → 下一步预测 → 进度检查 → 文字指导与缓存。模型观察到的“完成”与用户确认的“完成”分开记录。
- **Unity客户端**：回放观察帧、任务状态和指导，另有一个多帧环境问答页面。
- **评测工具**：在 GTEA、EgoTaskQA、Charades-Ego 等公开第一视角数据上，用相同输入对比多个视觉语言模型。

这是结构化的重新实现，不是原论文系统的完整复现。原系统还包括持续预测、并行完成检测，以及图像、语音、计时和空间提示等交互，并做了用户研究；这些尚未在本仓库中实现或验证。

## 主要结论

1. **高层任务目标识别较好。** Claude Opus 5.5 与 GPT-6.1-sol 都答对25/28个视频（89.29%）。所给的4帧覆盖整段视频，只能说明模型能事后概括整段任务。
2. **预测越远越难。** 三个 API 模型在0秒条件下答对24–29/32，提前3秒只剩11–12/32。
3. **任务问答的短板在多人互动和反事实推理。** 字面匹配最高22.50%，按语义判分 Claude 为36.50%；数据集归为多人互动类的13道题，三个 API 模型全部答错，反事实题按意思评分后几乎没有提升。
4. **本地部署的模型明显落后。** Mage-VL 和 VideoChat3-4B 三项分数都明显低于 API 模型；Dispider 没有产生符合评分格式的输出，这不代表它的视觉能力为零。
5. **Satori 流程能在真实短片上跑通。** 6个采样时刻得到15个阶段响应，可在 Unity 中回放；但还没有完整任务闭环和步骤级准确率。

## 实验怎么做

- 每题给模型4张按时间顺序排列、带时间戳的关键帧（Charades-Ego 为8帧），不是连续视频。七个模型收到的图片、时间戳和问题完全相同（各模型内部的预处理和调用方式不同），标准答案不进入请求。
- 每题只请求一次，不重试、不修改模型回答。接口失败、输出格式不合要求和弃答都计入分母、按错误计。Claude 的结果是按原始返回离线重新解析得到的（原采集脚本误判了一批合法回答），没有重新调用模型，详见实验简报。
- 各模型的推理档位没有统一（Claude 为 high，GPT 未指定）；GPT 名称是第三方接口的路由别名，底层权重未独立核验。

## 术语

| 术语 | 含义 |
|---|---|
| 关键帧 | 从视频中按固定规则抽取的少量静态图片，按时间顺序给模型 |
| 字面匹配 | 统一大小写、标点、英文冠词和空白后，答案与标准答案完全一致；任务问答的正式分数 |
| 语义等价 | 判分代理认为与标准答案意思相同；补充分析，不替代正式分数 |
| 弃答 | 模型按要求返回空答案，表示证据不足；计入分母、按错误计 |
| 前瞻时间 | 要预测的动作在观察截止后约多少秒开始（0、1、3秒） |
| micro-F1 | 把所有视频的动作识别结果合在一起计算的精确率与召回率的调和平均 |
| Fleiss κ | 多名判分者之间的一致程度，1表示完全一致，0表示与随机一致相当 |

## 局限

- 只在公开数据上做模块评测，评测协议没有完全对齐原论文：GTEA 按原始标注实测为73种动作（原论文为71类、按被试留一划分），EgoTaskQA 的200题是重新抽样，不是原论文所用题目。结果不是官方榜单成绩。
- 每题只有4张稀疏帧，可能缺少答题所需的证据；目前没有标注答案证据是否出现在这些帧中。
- 第三方接口时有限流和服务错误（例如 GPT-5.6-sol 的问答200题全部接口失败），相关低分不能直接解释为模型能力弱。
- 尚无完整任务交互闭环、提示时机评估和用户研究。

## 下一步

1. 在 Unity 中补完整任务闭环：确认目标、拒绝错误建议、完成和重做步骤，并用独立标注评价整段任务。
2. 固定模型，比较帧数、时间窗口和事件记忆，检查能否改善动作漏检和任务问答。
3. 测量主动帮助的实际收益：提示是否准确、是否及时，以及用户要等多久。
