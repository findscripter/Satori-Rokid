# Satori 复现与模型评测实验简报

日期：2026年10月18日（10月20日补充输入说明、问答示例和语义重评分，并补跑了三个 GPT 模型因接口错误缺失的题）

本阶段围绕“理解用户所处环境、正在做什么、下一步可能做什么”开展实验。已搭建 Satori 方法原型并接入 Unity，完成七个模型在公开第一视角数据上的对比。当前结果是：**高层任务目标识别效果较好，未来动作预测还有明显下降；在已做语义重评分的五个模型中，任务问答按意思评分最高约37%，涉及多人互动和反事实推理的问题仍然很弱。**

## 1. 跑了哪些实验

| 实验 | 数据与规模 | 给模型看的画面 | 测什么 |
|---|---|---|---|
| 任务目标识别 | GTEA，28个视频、7类目标 | 整段视频均分4段，每段取中间1帧 | 根据视频观察判断用户在完成什么任务 |
| 未来动作预测 | GTEA，32个目标事件，分别提前0、1、3秒预测，共96题 | 目标动作开始前的4帧，每秒1帧；提前1秒或3秒预测时，4帧整体再往前移1秒或3秒 | 根据之前的画面判断接下来发生的动作 |
| 任务相关问答 | EgoTaskQA，200题，涉及189个视频 | 整段视频均分4段，每段取中间1帧，另附英文问题 | 回答关于人物、物体、动作和事件关系的问题 |
| 环境与动作识别 | Charades-Ego，32段视频 | 整段视频均分8段，每段取中间1帧 | 识别场景和动作，比较 Mage-VL 与 GPT |
| Satori 流程演示 | EgoDex清洁短片，6个采样时刻 | 每个时刻取截至当时最近的1至4帧 | 验证环境理解、目标提议、下一步预测、进度检查和指导生成能否串起来 |

前三项为主实验，每个模型324题，七个模型累计2268个模型—样本结果，其中包含此前已完成的 Mage-VL 和 VideoChat3-4B 结果。模型看到的是按时间顺序排列、带时间戳的关键帧，**不是连续视频流**：本实验以图片输入调用 GPT 和 Claude，统一使用关键帧后，七个模型收到的图片、时间戳和问题完全相同；VideoChat3 和 Dispider 这类视频模型也接收这同样的4帧（Dispider 把每帧重复4次，填满它的16个输入位置），但各模型内部的预处理和调用方式不同。图片保持原始分辨率，不含音频和 IMU。目标识别从7类厨房任务中选一个（如做咖啡、做奶酪三明治、泡甜茶），动作预测从73种动作中选一个（如 take (bread)、open (honey)），候选表每题相同；问答则用英文短语自由作答。标准答案和视频文件名不进入请求，评分在推理结束后用数据集标准答案进行。

目标识别和动作预测报告准确率。问答的正式分数是**字面匹配率**：统一大小写、标点、英文冠词和空白后，答案须与标准答案完全一致。接口失败、输出格式不合要求和弃答（模型按要求返回空答案，表示证据不足）都计入总题数、按错误计。问答另做了一次语义重评分作为补充（见第3节），正式分数仍以字面匹配为准。

## 2. 七模型主实验结果

| 模型 | 目标识别，28题 | 动作预测，96题 | 任务问答，200题（字面匹配） |
|---|---:|---:|---:|
| Claude Opus 5.5 | 89.29%（25/28） | 55.21%（53/96） | 22.50%（45/200） |
| GPT-6-astra | **92.86%（26/28）**† | **61.46%（59/96）**† | 19.50%（39/200）† |
| GPT-6.1-sol | 89.29%（25/28） | 55.21%（53/96）† | 21.00%（42/200）† |
| GPT-5.6-sol | 78.57%（22/28）† | 33.33%（32/96）† | **26.00%（52/200）**† |
| Mage-VL | 53.57%（15/28） | 6.25%（6/96） | 2.00%（4/200） |
| VideoChat3-4B | 32.14%（9/28） | 5.21%（5/96） | 4.00%（8/200） |
| Dispider | 未获得合格输出 | 未获得合格输出 | 未获得合格输出 |

*†含10月20日补跑的缺失题。补跑前（10月18日）的成绩：*

- *GPT-6-astra：67.86%（19/28）、60.42%（58/96）、19.50%（39/200）；*
- *GPT-6.1-sol：54.17%（52/96）、17.50%（35/200），目标识别没有缺题；*
- *GPT-5.6-sol：67.86%（19/28）、13.54%（13/96），问答200题全部接口失败。*

*Dispider 的输出未满足本轮评分格式要求，不能解释为视觉能力为零。Mage-VL 和 VideoChat3-4B 也受到接口或输出格式问题影响。*

**10月20日补跑。** 10月18日这三个 GPT 模型共有290题因接口错误（HTTP 429、502、503 和连接失败）没有拿到回答，当时按错误计。10月20日网关恢复后，按事先冻结的协议，把这些题用与原来完全相同的请求重新问了一遍，一次只发一个请求。第一轮有27题再次被网关以并发超限拒绝，第二轮补齐。现在这三个模型的每一格都没有失败题；290题中有3题是模型弃答，按错误计。

使用这些数字时需要注意：

- 补跑比原始请求晚两天，第三方别名背后的模型可能已经变化。成功的题没有重跑，所以带†的格子混合了两个时间点的回答；GPT-5.6-sol 问答的200题则全部是10月20日的回答。
- 补跑的题不是随机抽的，失败集中在网关拥堵的时段。例如 GPT-6-astra 目标识别补回的7题全部答对，GPT-5.6-sol 问答第二轮补的18题全是是非题。
- GPT-5.6-sol 问答的26.00%比 Claude 的22.50%只多7题。两者的采集时间和推理档位都不同，补跑的新答案也没有做语义重评分（Claude 的语义分是36.50%），所以不宜据此排序。

补跑的完整记录（逐题请求记录、首次请求前冻结的协议和核对结果）保存在本地实验工程中；其中含数据集题目原文，按本仓库不分发数据集的约定未上传。

模型名称按简称展示。实际主实验中 Claude 使用 high，GPT 未显式指定推理档位；因此这里比较的是各模型在当前接入配置下的表现，未完全控制内部推理预算。GPT 和 Claude 都经第三方接口或通道调用，模型名沿用其别名，底层权重未独立核验。10月18日部分 GPT 结果因限流分批续跑，当时只续跑从未尝试过的题目；仍因接口错误失败的题在10月20日补跑（见上文）。Claude 的原始采集脚本把同一轮回复中的思考和正文分段误判为不合格，标为失败的有309条（目标识别15条、动作预测95条、问答199条）；表中 Claude 结果是对保存的原始返回统一重新解析得到的，拼接后的最终文本须与原始最终结果逐字一致，没有新增模型请求，也没有修改答案。

## 3. 效果说明

**任务目标识别较好。** GPT-6-astra 答对26/28个视频（92.86%，含补跑），Claude 和 GPT-6.1-sol 均答对25/28（89.29%）。不过这里使用了覆盖完整视频的4帧，主要说明模型能概括整段任务，尚不能证明任务刚开始时就能识别目标。

**预测距离越远，准确率越低。** 三个表现较好的模型在不同预测时距下的结果如下，每一格均为答对题数/32：

| 模型 | 0秒 | 提前1秒 | 提前3秒 |
|---|---:|---:|---:|
| Claude Opus 5.5 | 24/32 | 17/32 | 12/32 |
| GPT-6-astra | 29/32 | 18/32 | 12/32 |
| GPT-6.1-sol | 27/32 | 15/32 | 11/32 |

GPT 两行含10月20日补跑：GPT-6-astra 提前3秒从11/32变为12/32，GPT-6.1-sol 0秒从26/32变为27/32。图中只在0、1、3秒有测量点，连线不代表2秒的结果；3秒处 Claude 和 GPT-6-astra 都是12/32，两点重合。

![三个API模型的动作预测准确率随前瞻时间下降](images/forecast-horizon.png)

0秒条件的最后观察帧也早于目标动作起点。结果表明，判断紧接当前观察的动作相对容易，提前更久判断用户意图仍有困难。

**任务问答按字面评分明显偏低，真正的短板在多人互动和反事实推理。** 按字面匹配，Claude 为22.50%（GPT-5.6-sol 补跑后为26.00%，见第2节说明），而所有题固定回答“no”的简单基线就有18%；Claude在68道是非题中答对43题，在132道查询题中仅答对2题。逐题检查发现，查询题的标准答案使用数据集内部标签词，例如 `bottle-water`、`watermelon1`、`poweredness`，意思正确的自由作答也会被判错。下面是一道真实题目（引自 EgoTaskQA 公开数据）：

| 项目 | 内容 |
|---|---|
| 画面 | 4张客厅关键帧：前3帧电视开着，第3帧画面下方能看到一只手，第4帧电视已关 |
| 问题 | How did the person changed the poweredness of the last object that has status change in the video?（这个人是怎么改变视频中最后一个发生状态变化的物体的通电状态的？） |
| 标准答案 | `Turn off TV with remote` |
| Claude 回答 | `turned off the TV using the remote control` |
| 判分 | 字面匹配判错；语义重评分判为等价 |

为此补充了一次语义重评分：

| 模型 | 字面匹配 | 语义等价 | 含部分正确 |
|---|---:|---:|---:|
| Claude Opus 5.5 | 22.50%（45/200） | **36.50%（73/200）** | 39.50%（79/200） |
| GPT-6-astra | 19.50%（39/200） | 31.00%（62/200） | 33.00%（66/200） |
| GPT-6.1-sol | 17.50%（35/200） | 27.50%（55/200） | 29.50%（59/200） |
| Mage-VL | 2.00%（4/200） | 4.00%（8/200） | 7.50%（15/200） |
| VideoChat3-4B | 4.00%（8/200） | 6.00%（12/200） | 8.00%（16/200） |

表中语义分数只用三个判分代理的多数票。主控 AI 曾对13项给出裁决，但主控就是被评模型之一 Claude Opus 5.5，存在利益冲突（其中4项“语义等价→部分正确”的降级都落在 GPT 的答案上），所以不计入主结果；若计入，GPT-6-astra 为29.50%、GPT-6.1-sol 为26.50%，排名不变。

语义重评分基于10月18日的原始回答，没有纳入10月20日补跑得到的新答案。因此本表中 GPT-6.1-sol 的字面匹配仍是补跑前的17.50%，GPT-5.6-sol 不在表中。

提升全部来自查询题，例如Claude从2/132升到30/132；是非题不受影响。按意思评分后，数据集归为多人互动类的13道题（多数问“另一个人在做什么”），三个API模型仍全部答错；40道反事实题中，Claude也只从11题升到12题。这两类才是当前真正的短板。四帧观察可能缺少关键证据，但还不能把低分全部归因于帧数。

语义重评分由三个独立的Claude Haiku 5.5判分代理盲评（看不到模型名称），只比较答案文字的含义、不看视频，按多数票定标签。真实答案中三票完全一致的占92%（Fleiss κ 0.86），40个故意配错的对照答案无一被判为正确；之后又做了正反两向的复核。判分和复核代理都是 Anthropic 的模型，与被评的 Claude 同属一家；盲评只隐藏了模型名，答案的文风仍可能透露来源。这是看到结果后追加的补充分析，全程没有人工标注；题目是重新抽样的，原论文对这些题的评分方式本项目也没有核实，所以不能与原论文的分数直接比较。

**当前本地模型配置整体落后于表现较好的API模型。** Mage-VL和VideoChat3-4B的动作预测、任务问答分数较低。除了理解能力，输入适配和结构化输出稳定性也需要改进；Dispider本次尚未形成可用的评分输出。

## 4. 其他已完成实验

### Charades-Ego环境与动作识别

在固定32段视频、每段8帧的条件下，动作识别结果如下，micro-F1综合考虑动作识别的精确率和召回率，越高越好：

| 模型或基线 | 动作识别 micro-F1 |
|---|---:|
| GPT-5.6-luna | 31.21% |
| 固定训练频率基线 | 17.82% |
| Mage-VL | 16.42% |

GPT优于Mage。GPT的动作召回率只有19.13%，但标准答案是整段视频里出现过的全部动作（32段共345个，平均每段约11个），8张稀疏帧不一定都拍到，所以召回率低不能全算作模型漏检。数据集的官方指标是 mAP，需要模型对每类动作给出连续的置信分；本实验只让模型输出动作标签，所以报告 micro-F1。32段视频取自4类场景（各8段）、11名参与者，只覆盖数据集的一部分。在两个模型都成功返回的28段视频上，场景识别均答对15段。这个实验说明，识别场景和识别具体动作的难度不同，不能用场景识别结果代替任务理解效果。该实验独立于上面的七模型主实验。

### Satori与Unity流程演示

用真实清洁视频完成了6个时刻的输入，窗口逐步从1帧增加到4帧，得到15个阶段响应。环境与行为理解、目标提议、下一步预测、进度检查、文字指导和指导缓存均已运行，结果可在Unity中回放查看。

本次验证了流程可运行，但最后步骤仍处于执行状态，没有完成整项任务，也没有独立步骤标签来计算准确率。完整任务交互、真实眼镜相机与IMU融合、提示时机和用户体验仍待验证。

## 5. 当前结论与下一步

目前已完成**Satori方法原型、Unity回放展示，以及公开数据上的模块benchmark**。现有结果支持继续研究时序任务理解：模型较擅长概括高层目标，但具体动作、较远未来预测，以及涉及多人互动和反事实推理的问答仍有明显不足。当前评测尚未完全对齐原论文协议，不能据此宣称完整复现Satori的系统效果。

下一步优先推进三项工作：

1. **补完整任务闭环。** 在Unity中支持确认目标、拒绝错误建议、完成步骤和重做步骤，并用独立标注评价整段任务。
2. **比较时序输入和记忆。** 固定模型与其他设置，比较不同帧数、时间窗口和事件记忆，检查是否改善动作漏检和任务问答。
3. **验证主动帮助的实际收益。** 测量提示是否准确、是否及时以及用户等待时间；之后再加入真实同步IMU与眼镜采集。
